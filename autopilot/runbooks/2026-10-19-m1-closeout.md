## Lessons from run 1, now rules

1. **Never pipe the test run before `&&`.** `… | tail && git push` hides a failing exit code, and run 1
   pushed a red suite that way. Run the push command exactly as written, unpiped. If you want less
   output, write it to a file and read the file afterwards.
2. **Record evidence in files, not only in console output.** For every number the debrief claims
   (eval miss rates, mutation results, dry-run counts), save the raw output under `data/evals/runs/`
   or `autopilot/evidence/2026-10-20/`, and cite the path. The QA agent marked eight claims "Not verified"
   in run 1 for lack of exactly this.
3. **A gate is changed only with its own decision log entry**, saying what it accepted before and what
   it accepts now. No gate is loosened to get an edition published.
4. **Keep the step table current.** Run 1's table still said "Not started" for a step that had run.

## The work, in order

### Step A · A failed week can be rerun (rows 8 and 11)

Today the run id is the week key, and a done stage is immutable, so a week whose gates fail can never
be reframed. Run 1 worked around this by publishing under an older key, `2026-W40`, which is why the
live edition is mislabelled.

- Let a week have numbered attempts: the run id becomes `2026-W43` for the first attempt and
  `2026-W43-r2`, `-r3` and so on for later ones. Widen the `runs.id` CHECK accordingly with an additive
  migration, and keep all the existing triggers. A new attempt starts at the Reader by default; add a
  `--reuse-reader <run-id>` option that starts from an earlier attempt's done Reader output, so a
  reframe does not re-fetch.
- At most one **published** edition per week. Publishing attempt 2 when attempt 1 already published is
  refused.
- **Label an edition by the window its Reader actually read**, stored in the Reader's output (for
  example "Oct 10 – Oct 18, 2026"), never by the run key. Fix how the live W40 edition displays: briefs
  are append-only, so derive the label from the stored Reader window or the publish date, and do not
  rewrite the brief.
- Mark superseded failed attempts in the status view. The W41 and W42 runs stay as they are; they are
  evidence.

### Step B · The faithfulness gate catches the planted fabrication (row 10)

This is M1's exit criterion: "faithfulness and structural gates green on a golden week **including a
planted fabrication**". Today the grader misses the planted `$965B` in `negative-01` every time.

- Build `bk-retry` exactly as designed in `plan/roadmap.md`: **any lift on a unit retries that unit,
  once.** `lifted_claims()` already exists in `agents/framer.py`. Row 10's "port, do not extend" no
  longer applies: the port is done and verified, so a change now can be attributed.
- The design says it "ships with more negative cases, not before them". Add **at least three new
  planted-fabrication cases** (a changed number, a changed date, an invented attribution) under
  `data/evals/negative/`, as new files. **`data/evals/golden/` stays untouched.**
- **Measure it, five paid runs per case**, the same way the 2026-09-15 baseline did: the miss rate on
  each planted case, and the false positives on the clean golden day. Save the raw results to files.
  Done means every planted fabrication is caught in at least 4 of 5 runs with 0 false positives on the
  clean day. If it falls short, do not fit thresholds to pass: record the numbers, mark the step
  Blocked, and say what you would try next.
- Rerun the weekly gate tests. Paid-call spend for this step should stay under $3.

### Step C · Sources from the old digest's catalogue (row 8)

`config/digest-sources.md` is the old digest's source catalogue, copied on 2026-10-19. It is the
"91-domain list".

- Seed `sources` from it, with tiers as labelled in the file, in addition to what is there now. Do not
  invent domains; a source the file names without a fetchable address is added as unaddressed.
- Add feeds or indexes for the labs and sources with none today, prioritising Anthropic's **two
  indexes** (news and research), OpenAI's two, Meta AI, Mistral, NVIDIA's developer blog, the Gemini
  API changelog and Microsoft AI. Verify each feed or index URL by fetching it once; never guess one.
  Where a site has no feed, use its index page through the web fetch path, with the dating rules in the
  file (some indexes show no dates; open the post to date it).
- Turn the file's "fetch and dating rules" into code where they are mechanical: the known-blocked
  domains, never guessing slugs, the primary source's date over coverage dates.
- Keep the per-run fetch cap and the $3 per-run ceiling. Record the new candidate counts from a free
  dry run, saved to a file.
