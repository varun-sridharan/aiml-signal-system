# AI/ML Signal design system

AI/ML Signal is a personal, weekly signal-over-noise system for a technical product leader: a pipeline reads the week's AI/ML news, verifies claims against their sources, and publishes one edition a week. The site has five pages that share one visual language: **Product** (the landing page), **Weekly Digest** (the edition), **System Design**, **Roadmap & Backlog** and **Plan & Progress**.

This system was derived from the pages in this project, not from an external codebase or Figma file:

- `Product.dc.html` (generated by `build-product.js` from `Product.json`)
- `Build Plan.dc.html` (generated by `build-plan.js` from `Plan.json`)
- `Weekly Digest Template.dc.html` and its slot list `Weekly Digest Slots.md`

Every value below was read from those files. Where the three pages disagreed, the Weekly Digest template wins for reading surfaces and Product wins for site chrome.

## Content fundamentals

- **Voice.** Plain, matter-of-fact, second person where the reader is addressed ("Edit if it's off", "You are reading last week's edition"). First person only in the founder's own story on Product.
- **Headlines state a consequence or a fact, not a topic.** "Agent tools now ship with a permission manifest", never "Agent permissions update". Contrast pairs are a house form: *Capability got cheaper. / Judgment didn't.*
- **One highlighted phrase per headline**, at most about five words, marking the turn. The rest stays in ink.
- **Labels are small-caps mono with a trailing slash**: `WHY IT MATTERS /`, `TRY THIS WEEK /`, `01/`.
- **Empty states tell the truth in one line**: "Nothing quotable surfaced this week." "Quiet week. Nothing cleared the bar. Go build." Never a "coming soon" badge; a section that is not built is not rendered.
- **Numbers are specific and sourced.** A claim with a number carries its source link.
- **No em dashes, no emoji, no hype words.** Sentence case for headings; uppercase only in mono labels.

## Visual foundations

- **Ground.** A warm off-white reading page (`--paper` #F4F1E8) inside a slightly darker warm-grey surround (`--surround` #E8E2D4). Flat panels (`--panel` #FBF9F3) for tiles and tables; `--inset` #EFE9DC for quietly highlighted boxes. No imagery, textures, gradients or photographs.
- **Colour.** One brand accent, burnt amber `--accent` #B5502A, for active tabs, accent rules, footnote markers and link underlines. Darkened to `--accent-ink` #A3451F wherever it is headline text, to clear 4.5:1. Mustard `--active` #7A5F14 means work in progress and is never red. Green `--ok` #2F6B52 means verified / hit / done; red `--miss` #9B2F2F means miss / failed / not found. Nothing else carries colour.
- **Section hues.** The four Weekly Digest NEWS sections each own a muted hue: thread #B5502A, learning #2F5D7C, stories #8A4F7D (headline ink #7E4572), leaders #7A5F14. None is green or red. The hue appears on the section's arrow, kicker, highlight phrase, 3px left rule and sub-tab marker, and the label always shows, so colour is never the only cue.
- **Type.** Newsreader for headlines and body; IBM Plex Mono for kickers, labels, counts, dates and numerals; Public Sans for site body copy and nav. Reading scale: 44px headline, 18px body at 1.6. Site scale: 40px section heading, 17px body, 13px small, 10.5px micro, 38px display for stat values and step numerals only.
- **Rules, not boxes.** Hairlines (`--rule` #DED7C6) separate everything. A 1px ink rule marks a section start; a 2px accent rule sits under a headline; theme dividers are a full-width hairline with a centred mono label.
- **Corners.** Almost square: 2, 3, 4, 6px. Pills (999px) are the only round shape, plus 50% monogram circles.
- **Shadows and transparency.** None on the reading page. The one exception is the site header (93% paper with an 8px backdrop blur) and Product's glass stat tile.
- **Motion.** Disclosures open and close in about 150ms and never shift the page above them. No bounce, no fades for decoration.
- **States.** Hover changes colour only (soft to ink, or an accent-soft tint). Focus is always `outline: 2px solid var(--accent); outline-offset: 2px`. Pressed thumbs fill with the section colour.
- **Layout.** One reading column of 680px with a 220px right rail on wide screens, inside a 1080px page. Below 760px the rail drops under the column, tabs scroll horizontally and tiles stack. Site pages use full-bleed bands with a 1200px container and 120px vertical padding.

## Iconography

There is no icon font and no icon set dependency. Icons are rare and functional:

- **Unicode marks** carry most of the load: `▸ ▾` disclosure, `↗` external link, `↔` ties to, `✓` checked against source, `“` the quote mark, `→` card links.
- **Thumbs** are a single inline SVG path (1.6px stroke, round caps and joins), outline by default and filled in the section colour when chosen; thumbs down is the same path flipped.
- **Product's figures** use an inline `<symbol>` sprite referenced with `<use>`: each glyph sits in a disc tinted to 12% of its own colour, 1.6px round strokes, no fills, and no icon repeats on a page.
- No emoji, no decorative icons, no logo file. The brand mark is the wordmark set in type: **AI/ML Signal** with the period in `--accent`.

## Components

| Component | Use |
| --- | --- |
| `SiteHeader` | Wordmark lockup and five-item nav, identical on every page |
| `Nav` | The nav alone; exactly one active item |
| `Tabs` | ARIA tablist, `primary` or `sub` variant, with count pills and section colours |
| `Pill` | DO THIS / KNOW / RADAR, OPEN / HIT / MISS, DONE / IN PROGRESS / TO DO, POST / EXCERPT, or a count |
| `Hashtags` | One to four topics under a story headline |
| `StoryTile` | Numbered story, short or feature, with Why it matters, Try it, In 90 seconds, Ties to, sources and thumbs |
| `QuoteTile` | Leader quote with monogram, type badge and Why it matters |
| `Thumbs` | Useful / Not useful with the reason box after thumbs down |

**Intentional additions:** none beyond the components the brief named. `Nav` is split out of `SiteHeader` so a page can render the nav in a narrow layout without the wordmark.

## Caveats

- **Fonts load from Google Fonts.** No font files were provided, so there are no self-hosted `@font-face` binaries.
- **Component cards and the UI kit need the generated bundle.** They read `_ds_bundle.js`, which is produced once this project is set as a Design System.
- **This system lives inside the site project.** Its files (`styles.css`, `tokens/`, `components/`, `guidelines/`, `ui_kits/`) sit alongside the page sources and do not change any page.
